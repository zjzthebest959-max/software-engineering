# 校园活动管理系统 V2.0（课程任务 / 真人私聊）

前端：index.html、styles.css、app.js，纯原生 JavaScript，使用 fetch 调用 Supabase API，无 npm 依赖。

## 当前状态

本地已增加真人一对一文字聊天：按学生、教师、系统管理员筛选联系人、按姓名搜索、加载历史、失败重试。保留 V1 用户名密码登录、教师发布和学生报名。**本次只修改本地文件，没有推送或部署，也没有执行云端 SQL。** 当前 Supabase 尚未升级时，聊天会显示升级提示，不能真实收发；不会用模拟回复假装联网成功。

双击 `启动系统.bat` 或 `index.html` 打开浏览器。真实登录和聊天需要联网，并完成以下一次性 Supabase 配置；本地 HTML 可以连接云端，不要求先部署到 Render。当前尚未执行这些云端操作。

用户名使用 3–32 位字母、数字或下划线，不区分大小写；姓名可使用中文；密码 8–128 位。底层把用户名映射到 `用户名@accounts.campus-demo.example`，仅作为 Supabase Auth 内部账号标识，不是真实邮箱，不收发邮件。密码仍由 Supabase Auth 管理，不自行存储明文密码。此 Demo 暂不支持邮件找回密码。

## 免费部署

1. 登录 Supabase Dashboard，新建 Free 组织下的项目。仅选择免费档，不启用付费升级。
2. 已有项目：先执行 `upgrade-v1-auth.sql`，再执行 `upgrade-v2-chat.sql`。两份升级脚本可以重复执行，不删除账号、任务或报名，也不改变已有用户身份。新项目只执行一次 `database.sql`，已包含 V1 与 V2 结构；不要在现有项目重新执行初始化脚本。
3. 在项目 API 设置复制 Project URL 和 publishable key（或旧版 anon key），填入 index.html 顶部两个对应的 meta 标签。公开密钥可以出现在前端；绝不可填入 secret key、service_role key 或数据库密码。
4. 在 Supabase Authentication 的注册设置中关闭 `Confirm email`，保持邮箱密码注册开启。这是一次性项目配置，不需要每位用户提供邮箱。官方说明：https://supabase.com/docs/guides/auth/general-configuration 。未关闭时前端会阻止注册，避免产生无法验证的账号。
5. 学生和教师均可自行注册，无邀请码。角色在创建账号时存入业务表，不会随以后修改 Auth metadata 自动改变；所有任务写入仍由数据库校验身份和所有权。公开教师注册只适合课堂演示，不代表验证了真实教师资格。
6. 用户批准推送后，将前端发布到现有 Render Static Site。使用仓库根目录 render.yaml：Root Directory 为 campus_activity_system，构建命令 `mkdir -p public && cp index.html styles.css app.js public/`，Publish Directory 为 `public`。不要公开发布整个项目目录中的 SQL 和测试文件。
7. 当前 Render 服务自动部署关闭，未来明确允许发布时才推送并手动部署。目前本地页面为 V2.0，现有线上版本保持不变。

旧邮箱账号及其任务保留，不会自动合并到新用户名账号。旧账号如需沿用，应由项目管理者通过 Supabase Auth 管理功能将登录标识改为相应的内部用户名地址，保留用户 UUID；切勿删除重建，否则原任务所有权不会随之转移。

## 功能和规则

- “课程任务 / 消息”双页面。消息页按身份筛选及姓名搜索真实联系人，排除自己；联系人分页每次 50 人。
- 双方私聊，文字 1–2000 字符，自己的气泡靠右；Enter 发送、Shift+Enter 换行，输入法选字不发送。
- 最近 50 条消息与更早历史分页；聊天页可见时每 5 秒刷新，隐藏页面或退出后停止聊天轮询；不是即时推送。
- 网络失败保留输入与原记录；同一次发送重试使用相同请求 ID，服务器避免重复写入。界面“已保存”不代表对方已读。
- 所有消息接口以 auth.uid() 确定用户，只允许读写自己的对话；管理员没有查看他人对话的业务接口。数据库项目所有者仍有维护权限，不是端到端加密。
- 系统管理员账号不开放自助注册。由项目所有者将指定现有 profile 的 role 改为 admin；升级脚本末尾有模板。不随意输入 UUID，不删除重建账号，不在前端配置管理员密码。
- 无 AI 自动回复、群聊、文件、图片、音视频、撤回或已读回执，保持课程 Demo 范围。

- 教师发布、编辑和取消自己的任务；查看自己的任务报名名单。
- 学生浏览任务、按课程筛选、报名和查看自己的报名记录，无创建/编辑入口。
- 任务保留课程、分类、优先级及报名截止时间。
- 取消保留报名历史；已取消、已截止或重复报名由数据库拒绝。
- 列表每 20 秒刷新，可手动刷新；联网后从云端重新读取。网络失败不伪装成功。
- 数据表启用 RLS 并撤销客户端直接访问权限，仅公开明确鉴权的函数。身份来自 auth.uid()；前端不能传入或伪造操作人。
- 密码由 Supabase Auth 处理，不写入代码或业务表。localStorage 仅保存当前登录会话，不保存任务、报名数据。

## 上线前真实验收

在两台设备 / 两个独立浏览器分别注册教师和学生，再以相同用户名登录：

1. 教师发布软件工程任务，设未来报名截止时间。
2. 学生刷新并看到该任务，点击报名；教师刷新名单后能看到学生。
3. 刷新或重新登录，报名仍存在。
4. 同一学生重复报名被数据库唯一键拒绝；两名不同学生都可以报名。
5. 学生调用发布/编辑接口、非发布教师调用报名名单接口均应失败。
6. 教师取消任务后学生不能继续报名；已报名记录仍可查询。
7. 手机和笔记本检查表单、弹窗、筛选、加载与网络错误状态。

上述云端验收需要真实项目配置，不能用本地模拟测试替代。

本地回归命令（在项目目录运行）：

```text
E:\node.exe --check app.js
E:\node.exe tests\auth-contract.cjs .
E:\node.exe tests\chat-contract.cjs .
```

以上运行真实前端 JS，模拟 DOM / HTTP 边界，不等同于真实浏览器排版或服务端权限验证。SQL 测试 `tests/chat-permissions.sql` 仅用于独立测试数据库，创建隔离测试账号后回滚，覆盖收发权限、直接表访问拒绝、管理员隔离、消息校验、幂等重试、同时间分页及匿名拒绝；本机无 PostgreSQL 环境，尚未执行。不要将它对线上项目运行。

未来云端升级后的聊天验收：两个独立浏览器用学生、教师账号互发文字；刷新验证历史；第三个账号和管理员不能读取前两者私聊；切换联系人、断网重试、超过 50 条历史分页均正确。浏览器视觉及真实跨设备收发待验证。
